```sql
-- User notification count and recent activity
SELECT 
  u.email,
  COUNT(n.*) as total_notifications,
  COUNT(CASE WHEN n.read_at IS NULL THEN 1 END) as unread_count,
  MAX(n.created_at) as last_notification
FROM users u
LEFT JOIN notifications_new n ON u.id = n.user_id
WHERE u.email = '[USER_EMAIL]'
GROUP BY u.id, u.email;

-- User preferences overview
SELECT 
  notification_type,
  category, 
  enabled,
  channels,
  frequency
FROM notification_preferences
WHERE user_id = (SELECT id FROM users WHERE email = '[USER_EMAIL]');

-- Recent delivery issues for user
SELECT 
  type,
  title,
  created_at,
  delivered_at,
  failed_at,
  channels
FROM notifications_new 
WHERE user_id = (SELECT id FROM users WHERE email = '[USER_EMAIL]')
  AND created_at > NOW() - INTERVAL '7 days'
ORDER BY created_at DESC;

-- System-wide error patterns
SELECT 
  DATE_TRUNC('hour', created_at) as hour,
  COUNT(*) as total,
  COUNT(CASE WHEN failed_at IS NOT NULL THEN 1 END) as failed,
  ROUND(COUNT(CASE WHEN failed_at IS NOT NULL THEN 1 END) * 100.0 / COUNT(*), 2) as error_rate
FROM notifications_new
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY DATE_TRUNC('hour', created_at)
ORDER BY hour DESC;
```

#### 📖 Knowledge Base - Troubleshooting Guide

```yaml
🔍 Guía de Troubleshooting Paso a Paso:

🚫 Problema: "No recibo notificaciones"

Diagnóstico Step-by-Step:
  1. ✅ Verificar user preferences:
     - ¿Notificaciones habilitadas para el tipo específico?
     - ¿Canales configurados correctamente?
     - ¿Filtros de prioridad no bloqueando?
     
  2. ✅ Verificar delivery status:
     - Query: SELECT * FROM notifications_new WHERE user_id = X AND created_at > NOW() - INTERVAL '1 day'
     - Check delivered_at vs. failed_at timestamps
     - Revisar failure reasons en logs
     
  3. ✅ Verificar device/channel specific:
     - Push: Token válido en push_subscriptions?
     - Email: Email address válido y no bouncing?
     - SMS: Número telefónico válido?
     
  4. ✅ Test notification:
     - Enviar test notification para verificar end-to-end
     - Monitorear logs durante test
     
  5. ✅ Escalación si persiste:
     - Compilar findings de steps 1-4
     - Incluir user ID, notification IDs afectados
     - Escalar a Level 2 con información completa

🐌 Problema: "Notificaciones llegan con delay"

Diagnóstico Step-by-Step:
  1. ✅ Verificar queue status:
     - Redis queue depth: redis-cli LLEN notification_queue
     - Processing rate: Monitor dashboard
     
  2. ✅ Verificar external service latency:
     - Firebase FCM response times
     - SendGrid API response times
     
  3. ✅ Database performance:
     - Query: SELECT pg_stat_activity() para identificar slow queries
     - Check recent performance metrics
     
  4. ✅ User-specific vs. system-wide:
     - ¿Otros usuarios reportando mismo issue?
     - Comparar delivery times entre usuarios
     
  5. ✅ Escalación criterios:
     - Delay >5 minutos: Escalación a Level 2
     - Multiple users affected: Escalación inmediata
     - System-wide degradation: Emergency escalation

🔄 Problema: "Configuración no se guarda"

Diagnóstico Step-by-Step:
  1. ✅ Browser/App issues:
     - ¿JavaScript errors en browser console?
     - ¿App version actualizada?
     - Test en different browser/device
     
  2. ✅ API response verification:
     - Network tab: ¿API calls returning 200?
     - Response body: ¿Errors en API response?
     
  3. ✅ Database verification:
     - Query preferences table para verify save
     - Check for constraint violations
     
  4. ✅ Permissions verification:
     - ¿User tiene permisos para modificar preferences?
     - ¿Session válida y no expirada?
     
  5. ✅ Cache issues:
     - Clear browser cache como test
     - Verificar Redis cache invalidation
```
