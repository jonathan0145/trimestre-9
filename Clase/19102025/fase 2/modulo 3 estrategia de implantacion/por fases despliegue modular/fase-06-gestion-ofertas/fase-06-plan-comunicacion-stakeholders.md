```yaml
  - Minimizar resistencia al cambio

Feedback:
  - Crear canales bidireccionales de comunicación
  - Incorporar input de stakeholders en desarrollo
```

## 🚨 Crisis Communication Procedures

### 🔴 Nivel 1: Crisis Crítica

#### Triggers
- Sistema down por >30 minutos durante business hours
- Security breach confirmada  
- Data loss significativa
- Launch completo fallido

#### Response Protocol (Primera Hora)
```yaml
Minute 0-15: Initial Assessment
  - Crisis team assembly
  - Impact assessment inicial
  - Stakeholder identification

Minute 15-30: Executive Notification
  - CEO/CTO notification inmediata (phone call)
  - Executive team emergency meeting convocation
  - Initial impact briefing

Minute 30-45: Stakeholder Alert
  - Key stakeholder notification (email + phone)
  - Customer-facing team briefing
  - Public communication preparation

Minute 45-60: Response Coordination
  - Action plan development
  - Resource allocation
  - Communication strategy finalization
```

#### Communication Templates
```yaml
Executive Alert Template:
  Subject: "URGENT: Phase 6 Critical Issue - Immediate Response Required"
  Content:
    - Issue description y scope
    - Current impact assessment
    - Immediate actions being taken
    - Next communication timing

Stakeholder Update Template:
  Subject: "Phase 6 Service Interruption - Status Update"
  Content:
    - Clear problem explanation
    - Impact on operations
    - Resolution timeline estimate
    - Alternative procedures (if available)

Customer Communication Template:
  Subject: "Temporary Service Issue - We're Working to Resolve"
  Content:
    - Service impact explanation
    - Expected resolution time
    - Alternative contact methods
    - Company commitment to resolution
```

### 🟡 Nivel 2: Issue Significativo

#### Triggers
- Timeline delay >1 semana
- Budget overrun >10%
- Key feature cancellation
- Major stakeholder conflict

#### Response Protocol (Primera Day)
```yaml
Hour 1: Problem Analysis
  - Issue severity assessment
  - Stakeholder impact analysis
  - Solution alternatives identification

Hour 2-4: Leadership Consultation
  - Executive team briefing
  - Decision-making session
  - Resource reallocation planning

Hour 4-8: Communication Preparation
  - Message development para each audience
  - Timeline adjustment planning
  - Stakeholder meeting scheduling

Day 1: Stakeholder Engagement
  - Individual stakeholder meetings
  - Revised plan presentation
  - Feedback collection y incorporation
```

### 🟢 Nivel 3: Issue Menor

#### Triggers
- Minor timeline adjustments
- Scope modifications
- Team resource changes
- User feedback concerns

#### Response Protocol
```yaml
Standard Process:
  1. Issue documentation
  2. Solution development
  3. Stakeholder notification via regular channels
  4. Progress monitoring
  5. Resolution confirmation
```
